# 商品规格汇总 API（2026-11-16 快照，接口口径更新于 2026-11-17）

面向前端 Claude Code。所有路由只读，继续使用现有 `/api/v4` 会话、签名和加密封装；未修改鉴权逻辑。

## 统一口径

- 商品目录包含 ChatGPT Go/Plus/Pro、Claude Pro/Max、Grok（Grok Plus/Premium/Super/Ultra 族）、Cursor、Muse、Gemini、Perplexity、Copilot、X会员、Telegram会员、Midjourney。Codex 不再是独立商品；Codex Go/Plus/Pro/Business/Team 报价分别归入 ChatGPT Go/Plus/Pro，额度包不作为订阅报价。`/tools/Codex` 返回 404。
- 三个起价路由都使用同一过滤与分组缓存：`/home`、`/tools/{name}`、`/catalog/{name}/specs`。剔除明确错配、最新采集状态为“需验证，暂无报价”的店铺；已售罄记录不计入。
- 周期从规格文本、标题解析并归一为 `1月`、`3月`、`6月`、`1年`、具体天数、次数或 `永久`。无法判断时统一进入 `时长未注明`，不再按原始标题拆成大量组。档位大小写归一；额度、地区、交付形态和币种仍是规格维度。
- 起价只使用未标记异常的规格价，`starting_price` 与 `entry_price` 相等，且与 `entry_spec.key` 指向的规格最低价相等。标准入门档优先按商品配置选择（ChatGPT Plus=1月 Plus 代充；ChatGPT Pro=1月 Pro100 代充/兑换码；ChatGPT Go=1月 Go；Claude Pro=1月 Pro 代充；Muse=10亿 Token；Gemini=Pro 成品号），过滤区域价和促销价；其他商品先选非区域、非促销月档。币种优先 CNY；同价按稳定顺序排序。
- 规格的 `shop_count`/`listing_count` 保留全部有效在售报价的供给计数，即使个别价格被标记异常；异常报价本身不会成为最低价/最低价店铺。
- `/home` 的 60 秒汇总缓存和商品规格缓存均为只读内存缓存。规格缓存按数据库引擎、商品和最近成功采集批次区分，TTL 60 秒；`/catalog` 翻页读取同一缓存，避免每页重复归并。

## 起价初步质检规则

本规则是后续 DeepSeek 质检前的初步筛选，可通过环境变量配置：`AI_SHOPS_LOW_PRICE_MEDIAN_RATIO` 默认 `0.50`（有效范围 0.05–小于 1）；`AI_SHOPS_MIN_CNY_PRICE` 默认 `1.0` 元（有效范围 0–小于 10000）。同一标准商品、归一规格、币种内，标记标题明显表示教程、学生认证/仅认证、共享车位/拼车/合租、代付/代拍、批发起发、补差价、仅手续费或测试价的不可比报价；人民币价格低于配置下限也标记；同规格至少 5 个有效样本时，低于中位数配置比例的报价标为异常。产品、档位、交付的价格底线和 data_quality_hits.csv 的人工审阅动作会进一步标记或剔除报价。异常记录保留作证据，但不参与最低价或起价；低于中位数 30% 的极端价从比较组中剔除，低于 50% 的价格留档并待复核。低价线只用于 CNY，不影响其他币种。

异常报价保留在数据中：采集 JSON 的 `listings[]` 写 `price_anomaly`、`price_anomaly_reason`；导入后作为规格 JSON 字段保存。`/tools/{name}/offers` 的报价项也返回这两个字段。此规则只影响最低价和起价，不删除商品记录，也不替代后续人工/模型质检。

## 路由

### `GET /api/v4/home`

无 query 参数。`tools[]` 中包含整个标准目录，不再只返回有在售价的商品。

| 字段 | 类型 | 含义 |
|---|---|---|
| `tools[].name` | string | 商品或商品族目录名。 |
| `tools[].members` | string[] | 组成此目录项的标准商品名。 |
| `tools[].n_shops` | integer | 曾关联/提及这些商品的店铺数（来自关联表）。 |
| `tools[].n_selling` | integer | 当前有有效在售报价的店铺数。 |
| `tools[].n_offers` | integer | 有效规格组中的在售报价记录数，含被标记异常的报价。 |
| `tools[].n_specs` | integer | 归一后的规格组总数。 |
| `tools[].price` | number \| null | `starting_price` 的兼容同义字段。 |
| `tools[].starting_price` | number \| null | 经异常价过滤后的起价；与 `entry_price` 相同。 |
| `tools[].currency` | string \| null | 起价币种。 |
| `tools[].entry_spec` | object \| null | 入门起价规格，字段见下文，含稳定 `key`。 |
| `tools[].entry_price` | number \| null | 入门规格最低有效价；与 `starting_price` 相同。 |
| `tools[].entry_shop_count` | integer | 入门规格在售店铺数。 |
| `tools[].status` | string \| null | 无可信在售价时的短状态，如 `暂无报价`、`暂无可信起价，报价需核验`。 |

### `GET /api/v4/tools/{name}`

Path `name` 为标准商品/商品族名。Query 参数 `page` 默认 1、最小 1；`page_size` 默认 50，范围 1–100，越界返回 422。响应最多含 100 个 `specs[]` 元素。

| 字段 | 类型 | 含义 |
|---|---|---|
| `total` | integer | 规格组总数。 |
| `page` | integer | 当前页，从 1 开始。 |
| `page_size` | integer | 每页上限，默认 50、最大 100。 |
| `total_pages` | integer | 总页数；无规格时为 0。 |
| `n_specs` | integer | 与 `total` 相同，保留的兼容总数。 |
| `specs` | array | 当前页规格组；结构见“规格对象”。 |
| `entry_spec` | object \| null | 入门起价规格，其中 `key` 与 `specs[].key` 相同。 |
| `starting_price` / `price` | number \| null | 同一有效规格组价格函数返回的起价。 |
| `entry_price` | number \| null | 与起价一致。 |
| `note` | string \| null | 经过审核、面向用户的商品说明；不返回内部 reason/urls。 |

### `GET /api/v4/catalog/{name}/specs`

Query 参数与 `/tools/{name}` 相同。返回分页元信息、全体规格组计算的起价/入门档，以及当前页 `specs[]`。翻页使用已缓存的规范分组，不会每页重新归并一次报价。

响应中的 `total` 和 `n_specs` 都是规格组总数；`page`、`page_size`、`total_pages` 对应当前页信息；`specs` 仅包含当前页，最多 100 组。起价字段与 `/home`、`/tools/{name}` 使用同一个 `product_price_fields` 函数。

## 规格对象

`/tools/{name}` 和 `/catalog/{name}/specs` 的 `specs[]`：

| 字段 | 类型 | 含义 |
|---|---|---|
| `key` | string | 规格组标识，可传入 `/api/v4/tools/{name}/offers?spec=...`。 |
| `tier` | string \| null | 归一档位，如 `plus`、`pro100`、`max`。 |
| `period` | string | 归一周期；无法识别时为 `未注明周期`。 |
| `delivery` | string | `代充`、`成品号`、`兑换码`、`Token号`、`组合` 或 `未注明交付` 等。 |
| `label` | string | 面向用户展示的周期、额度、档位、地区和交付摘要。 |
| `currency` | string | 报价币种；不同币种单独分组。 |
| `lowest_price` | number \| null | 同规格有效报价最低价；异常价不会参与。若全组都异常则为 `null`。 |
| `lowest_shop` | object \| null | `{ "name": 店铺名, "public_shop_id": "公开数字ID" }`。不包含 `shop_key`、来源路径、备注或链接；公开 ID 可用于 `/api/v4/shops/{id}`。 |
| `shop_count` | integer | 有此规格在售报价的去重店铺数。 |
| `listing_count` | integer | 此规格去重后的在售报价条数。 |

`entry_spec` 形如：`{"key":"9:...:CNY","name":"1月 / plus / 代充","label":"1月 / plus / 代充","tier":"plus","period":"1月","delivery":"代充"}`。

## 报价来源与 Offers

`GET /api/v4/tools/{name}/offers` 保留既有 `page`/`size` 分页。每个 `items[]` 增加：

- `price_anomaly`：boolean，初步异常价标记。
- `price_anomaly_reason`：string \| null，标记原因。
- `verification_source`：string \| null，人工核实来源。此次 3 家人工浏览器核实报价值为 `浏览器核实 11-17`。

快照中对应 `listings[]` 项也使用 `verification_source` 字段。人工浏览器核实和本轮渲染浏览器抓回的报价分别使用 `浏览器核实 11-17`、`浏览器渲染核实 11-17`；普通自动采集报价不设置该字段。

`lowest_shop.public_shop_id` 只返回公开数字店铺 ID；`/shops/{id}` 的 `crawl_status` 只返回以下固定枚举：`采集成功`、`无报价`、`需验证`、`需要登录`、`店铺关闭`、`连接失败`、`结构未适配`、`已跳过`、`未知`，不会返回内部采集 reason、URL 或 Playwright 调试文本。

`GET /api/v4/shops?q=...` 仍支持原有搜索条件和分页；搜索字面值里的 `%`、`_`、反斜线均按普通字符匹配，不再作为 LIKE 通配符。

## 错误

- `404`：标准商品不存在。
- `401` / `403` / `429`：沿用当前会话、签名、来源检查和限流行为。
- `422`：分页参数越界。

## 本轮目录归并

- `ChatGPT Go` 是独立目录商品，起价档按 Go 订阅规格计算。
- Codex 档位标题从规格身份中移除：Go→ChatGPT Go；Plus→ChatGPT Plus；Pro/Pro100/Pro200/Pro500/Business/Team→ChatGPT Pro。同一店铺、同一归一规格的 Codex 来源报价只让最低价参与比较，较高报价仍保留在快照并带 `codex_duplicate_of`。
- Codex 额度包（例如 Codex 250/500/1000 额度）不并入订阅商品；快照保留报价和 `comparison_exclusion`，覆盖报告单独列出。
- `/home` 商品卡总数按标准产品目录的商品族归并结果计算（Grok 子商品合并为 Grok 卡）；无报价卡仍然返回，标记 `暂无报价`。
